# AWS、Microsoft Azure 与 Google Cloud 企业云战略 Reference

> Reference 模式：`evidence_scarcity_challenge`。本报告用于评价研究系统能否在财务、市场、价格、基础设施和主权云证据不完整时，仍形成严谨的企业云决策框架；它不是三家厂商完整事实金标准，也未经过人类审核。

## 1. 执行结论

截至 2026-07-15，固定来源不足以指定 AWS、Microsoft Azure 或 Google Cloud 为所有企业场景的统一主云。可直接审计的有限事实主要有：AWS 官方页将 AWS 描述为 Amazon 的一部分，并把客户范围描述为从初创和大型企业到非营利组织和政府；英国 CMA 调查英国公共云基础设施服务，并建议优先考虑对 Microsoft 和 AWS 的相关云服务数字活动启动战略市场地位调查。[aws-about] [uk-cma-cloud-investigation]

这些事实不能推出全球市场份额、技术领先或客户结果。CMA 建议也不是最终 SMS 指定或违法裁判。三家同期间财务、统一市场份额、截止日基础设施、同拓扑 SLA、工作负载总成本、主权云控制和 AI 容量均为 Unknown。

成熟决策应按场景建立三家短名单，使用代表工作负载、书面报价、合同审计和退出演练形成证据。只有某厂商在目标服务可用性、恢复目标、三年总成本、数据控制和退出测试中同时达到测试前冻结的门槛，才应成为该场景默认云。

## 2. 可比口径

| 维度 | 允许口径 | 禁止推导 |
|---|---|---|
| 财务 | 同报告期间、币种和云业务分部边界 | 把公司级、组合级和云分部指标混排 |
| 市场份额 | 同机构、IaaS/PaaS 定义、地区和统计期 | 用厂商收入或营销“领先”推导份额 |
| 基础设施 | 目标国家、独立故障域、关键服务和容量 | 直接比较 Region/AZ/Zone/Geography 数量 |
| SLA | 同服务、单区/多区拓扑、测量、排除和抵扣 | 用一个服务 SLA 代表整个平台可靠性 |
| 价格 | 同 Region、配置、币种、利用率、折扣和合同期 | 用列表价或免费额度宣布总体更便宜 |
| 锁定 | 出口、许可、承诺消费、托管服务、人员和迁移 | 把多云部署数量等同于可退出性 |
| 主权云 | 数据、人员、密钥、法律控制和 GA 状态 | 用产品名称或公告推导合规 |
| AI | 目标 Region 的 GA、容量、等待、性能和单位成本 | 用型号/模型清单推导实际供应能力 |

### 商业模式、GTM 与伙伴生态边界

当前固定来源不足以比较三家的直销与渠道模式、账户团队覆盖、支持层级、企业折扣、承诺消费灵活性、续约和终止条款。这些字段必须通过同一 RFP 的书面报价和合同红线比较，不能从公开列表价或品牌关系推导。

伙伴数量、Marketplace 条目或既有软件关系也不能自动证明实施更快或退出更容易。目标企业需要核验目标国家可交付团队、同类项目经验、实施工时、Marketplace 采购约束、许可协同收益、替代伙伴和退出后的支持连续性。在完成伙伴尽调和替代实施方案前，三家的生态与既有栈净收益为 **Unknown**。

## 4. 竞争机制与替代解释

CMA 案件页面分别列出出口费、许可实践和承诺消费协议等调查附录或工作论文。[uk-cma-cloud-investigation] 这证明这些主题进入英国调查材料，不等于 CMA 对每种机制、每家厂商或全球市场作出相同结论。这些机制对目标企业的实际影响仍取决于数据量、软件资产、合同期限和使用结构。

至少存在六类会改变表面排名的替代解释：

1. Region 数量更多，但目标国家缺少关键托管服务或容量。
2. 公开计算单价较低，但出口、日志、支持、许可和迁移成本更高。
3. 既有身份与办公生态降低短期迁移成本，但增加长期许可或退出依赖。
4. 更高的财务规模可能反映业务边界差异，不代表单位工作负载效率。
5. 多云合同或部署存在，但关键数据和托管服务仍无法在可接受时间内退出。
6. 主权云或 AI 能力已经公告，但目标 Region 尚未 GA、容量不足或控制边界不满足法务要求。

因此，单一规模、功能数量、列表价或品牌生态均不能作为主云决策代理。

## 5. 场景化短名单策略

### Microsoft 既有栈深、受监管企业

Azure 应进入短名单，但不能仅因既有 Microsoft 关系直接获胜。测试必须量化身份、终端、许可和数据栈协同收益，并检查许可限制、数据控制和退出成本。若协同收益没有覆盖三年合同与退出风险，则结论可翻转到 AWS、Google Cloud 或分层多云方案。

### 数据与 AI 原生团队

三家都应以同一训练/推理和数据处理工作负载进入 POC。比较目标 Region 容量、排队、数据移动、工程工时和单位成本。模型或加速器目录不能替代实际供应与生产性能。

### 全球基础设施型企业

先按业务国家、灾备距离、数据复制和关键服务建立位置矩阵，再比较厂商。若某厂商全球规模更大但目标国家服务缺失，不应成为该场景默认云。

### 高度关注多云和退出成本的企业

应优先测试数据导出时长、出口总成本、基础镜像/容器可迁移性、身份替换、托管数据库迁移和承诺消费未用余额。未完成一次退出演练前，不应把“支持多云”视为已验证能力。

## 6. 决策门槛与结论翻转条件

评审委员会应在 POC 和报价前冻结门槛：

- 目标国家和关键服务必须满足可用与容量要求。
- 架构必须满足 RTO/RPO，并明确客户与厂商责任。
- 三年总成本必须包括出口、许可、支持、迁移、双轨和退出。
- 数据驻留、人员访问、密钥和法律控制必须通过法务与安全审查。
- 关键数据和至少一个代表应用必须在规定窗口内完成退出演练。
- 合同中的承诺消费、涨价、审计和终止条款必须可接受。

若某厂商在某场景全部通过，可以成为该场景默认云。若只有生态或列表价领先，但恢复、控制或退出失败，则不得成为默认云。不同场景可以产生不同默认厂商，不要求一个综合冠军。

## 7. 最小补证计划

1. 固定三家同期 10-K/10-Q 或 Earnings Release，建立云业务口径字典。
2. 固定一份方法透明的独立市场报告，记录市场定义、统计期和地区。
3. 在同一天导出目标国家的 Region、故障域和关键服务可用矩阵。
4. 为计算、对象存储和托管数据库固定同拓扑 SLA 与条款版本。
5. 选取 Web/API、数据分析和 AI 三类代表工作负载，取得三家书面报价并运行 POC。
6. 使用同一 RFP 比较销售支持、折扣、承诺、续约、终止和合同红线；对伙伴能力和替代实施团队完成尽调。
7. 使用 CMA 调查材料中的出口费、许可和承诺消费维度完成合同审计。
8. 由法务、安全和采购核验主权云控制边界。
9. 对关键数据和一个代表应用执行退出演练，保存时间、费用、失败和人工工时。

本挑战集期望优秀报告在证据稀缺时仍能区分厂商自述、监管事实、Unknown 和企业验证门槛，而不是制造综合冠军，也不是仅用一句“资料不足”结束分析。
