# OpenCompete 源码逐模块讲解计划（模块全景图）

创建日期：2026-08-11
用途：按「自底向上、按依赖层级」的顺序，逐模块讲解 OpenCompete 源码实现。一次只深入一个模块，讲完一个模块后停下来等待确认，再进入下一个模块。

## 一、三大子系统总览

```
┌─────────────────────────────────────────────────────────┐
│ 子系统 C：外围支撑（benchmarks / tests / skills / frontend）│
├─────────────────────────────────────────────────────────┤
│ 子系统 B：竞品分析系统（src/opencompete/，OpenCompete 自研）│
├─────────────────────────────────────────────────────────┤
│ 子系统 A：Deep Research 引擎（src/open_deep_research/）    │
│             + 旧版对照（src/legacy/）                      │
└─────────────────────────────────────────────────────────┘
```

依赖铁律：A 不依赖 B；B 依赖 A；C 只读 B/A 的产物。方向不可逆转。

## 二、子系统 A：Deep Research 引擎（最底层）

来源：LangChain 官方 `open_deep_research` 仓库，固定基线 `b764481f`。职责：把「一个研究问题」变成「一份带引用的完整报告」。

| 层级 | 模块 | 行数 | 职责 | 依赖 |
|---|---|---|---|---|
| A1 | `state.py` | 152 | 定义图状态（AgentState / SupervisorState / ResearcherState 等）与结构化输出模型（ConductResearch、ResearchComplete、Summary…） | 仅 LangChain/LangGraph |
| A2 | `configuration.py` | 343 | `Configuration` 配置模型：搜索 API 选择、并发上限、模型名、token 上限等 | A1 |
| A3 | `model_routing.py` | 155 | OpenCompete 新增：模型单次调用重试与主备降级（`build_resilient_model`、`route_metadata`） | 仅 LangChain |
| A4 | `prompts.py` | 394 | 全部系统提示词模板（澄清、研究简报、Supervisor、Researcher、压缩、最终报告） | — |
| A5 | `utils.py` | 1485 | 工具定义（Tavily 搜索/提取、think 工具、MCP 客户端）、总结网页、消息压缩、token 预算检查 | A1、A2、A3、A4 |
| A6 | `deep_researcher.py` | 1548 | 引擎主体：Supervisor/Researcher 双子图 + 顶层 4 节点图（澄清→简报→研究→报告），导出 `deep_researcher_builder` 和 `deep_researcher` | A1–A5 |
| A0 | `src/legacy/*`（graph、multi_agent、state、prompts、utils、configuration） | ~1400 | 旧版「报告章节规划器」架构（先规划章节→逐章写作），与上游早期版本对应，仅供对照演进关系 | 独立 |

演进关系一句话：legacy 是「分章节写作」的单代理流水线；上游新架构演化为「Supervisor 规划分派 + 多个 Researcher 并行研究 + 最终报告节点综合」的双层多代理图。

## 三、子系统 B：竞品分析系统（上层，OpenCompete 自研）

职责：在 A 引擎之上做范围确认、结构化证据链、预算控制、安全校验、本地持久化、评测闭环。A 的 `deep_researcher_builder` 被 B 当作子图嵌入。

### B0 基础支撑层（最底层，谁都能依赖）

| 模块 | 行数 | 职责 |
|---|---|---|
| `models.py` | 661 | 领域数据契约：`FrozenModel` 冻结基类、`Source→Evidence→Claim→Comparison→ReportArtifact→RunBundle` 全链路模型、枚举、稳定 ID 生成 |
| `errors.py` | 72 | 错误分类体系：配置/认证/预算/Provider/数据校验/持久化错误，全部可判定是否可重试 |
| `security.py` | 360 | URL 白名单校验（只允许公开 HTTP/HTTPS，拒绝内网/本机）+ 诊断文本脱敏（API Key、Bearer、Authorization） |
| `settings.py` | 282 | 非秘密配置：`.env` + `opencompete.toml` + pydantic-settings，模型名/预算/重试参数 |

### B1 业务逻辑层

| 模块 | 行数 | 职责 | 关键依赖 |
|---|---|---|---|
| `analysis.py` | 310 | Analysis Packs（三层通用维度表）、构建草案范围、范围冻结校验、证据链硬门禁 | models |
| `research_contracts.py` | 216 | 把冻结范围编译为「内部契约」（给 Extractor/门禁/Supervisor）与「用户可读 brief」的分离构造 | models |
| `budget.py` | 587 | 原子预算预留/结算：`BudgetGuard`、`BudgetLedger`、可重试错误判定、确定性 call_id | model_routing、errors、security |
| `callbacks.py` | 808 | `BudgetCallback`：通过 LangChain `AsyncCallbackHandler` 在每次外部调用前预留、调用后按真实 token 结算 | budget、models |
| `providers.py` | 256 | Tavily 发现 Provider（惰性客户端、错误归一化），只做发现不改范围 | budget、errors、security、models |
| `extractors.py` | 306 | `ArtifactExtractor`：从研究文本提取受证据 ID 约束的结构化结论（模型版 + 静态测试版） | model_routing、models |
| `materialize.py` | 922 | 物化：把上游研究状态解析为 `RunBundle`（解析 SOURCE 块、校验证据链、脱敏、失败兜底） | extractors、reporting、security |
| `reporting.py` | 187 | 确定性 Renderer：最终报告失败时，从已验证结构化关系渲染可读保底报告（不含内部 ID） | models |
| `report_publication_gate.py` | 236 | 发布前 Markdown 确定性门禁：内部标识泄漏/裸 Unknown/缺来源/缺决策摘要/语言一致性等，硬错误阻断发布 | models |

### B2 编排层

| 模块 | 行数 | 职责 | 关键依赖 |
|---|---|---|---|
| `graph.py` | 420 | 外层图：范围确认流程（durable `interrupt`）+ 嵌入上游 `deep_researcher_builder` 子图 + 物化/门禁节点 | 上游 A6、analysis、materialize、providers |
| `persistence/` | 6 文件 | `SqliteCheckpointStore`（Checkpoint 恢复真相源）、`SqliteExecutionLedger`（确定性调用账本）、`RunRepository`（历史产物）、`reconcile`（按 run_id+revision 对账） | models |
| `application.py` | 1196 | 应用编排核心：编译 Graph、注入 Checkpointer、组装预算/回调/锁、创建/恢复 run、评测入口 | 几乎全部 B1+B2 |
| `cli.py` | 910 | 交互式命令行入口（rich 渲染），只调 Application 层，不碰 Graph/SQLite/Tavily | application、settings |
| `drb_cli.py` | 167 | 官方 RACE 生成/评分/量化摘要独立命令 | evaluation、deep_researcher |

### B3 评测层（读历史产物，不重新搜索）

`evaluation/`（18 文件）：`hard_gates.py`（确定性硬门禁）、`official_drb.py`（固定官方 Deep Research Bench 工具）、`drb_runner.py`、`judge.py` / `service.py` / `models.py`（OpenCompete 本地 RACE/FACT Judge）、`competitive_v3_*`（v3 竞品评测套件）、`competitive_calibration.py`（评测校准）等。

## 四、子系统 C：外围支撑（简要）

| 目录 | 与核心的关系 |
|---|---|
| `benchmarks/` | opencompete v1/v2/v3 基准任务集，供评测层消费 |
| `tests/` | 离线测试（含模拟 Provider/模型），不得依赖 Agent Server 与 langgraph.json |
| `.agents/skills/` | 四个技能：面试拷问、项目学习、复盘、简历写作，消费核心源码与真实 Run 产物 |
| `frontend/` | Vue 3 演示前端，第一版正式产品是 CLI，前端只是展示层 |
| `docs/` | 架构设计、取舍记录、真实测试报告 |

## 六、讲解顺序（自底向上，共约 15 站）

1. A1 `state.py` — 引擎的数据契约（顺带讲透 Pydantic、TypedDict、reduce 操作符）
2. A2 `configuration.py` — 配置模型（顺带讲 RunnableConfig 的 configurable 机制）
3. A3 `model_routing.py` — 模型路由/重试/降级（`with_retry`、异常白名单）
4. A4 `prompts.py` — 提示词体系（快速带过，重点讲与架构的对应）
5. A5 `utils.py` — 工具层（`tool`/`StructuredTool`/`InjectedToolArg`、MCP、消息压缩）——最烧脑的一站
6. A6 `deep_researcher.py` — 引擎主体（StateGraph、条件边、子图嵌套、并行并发）
7. A0 legacy — 旧版对照（简述演进关系）
8. B0 `models.py` → `errors.py` → `security.py` → `settings.py`
9. B1 `analysis.py` + `research_contracts.py`（范围冻结与契约）
10. B1 `budget.py` + `callbacks.py` + `providers.py`（预算与外部调用）
11. B1 `extractors.py` + `materialize.py` + `reporting.py` + `report_publication_gate.py`（产物物化与门禁）
12. B2 `graph.py`（外层图 + durable interrupt）
13. B2 `persistence/`（Checkpoint 恢复 + 账本 + 对账）
14. B2 `application.py` + `cli.py` + `drb_cli.py`（编排与入口）
15. B3 `evaluation/` + 子系统 C（简要带过）

## 七、讲解规范（硬性要求）

- 默认听众完全不懂技术栈；禁止「众所周知」「显然」等省略性表述；术语第一次出现必须给出通俗定义和例子。
- LangChain / LangGraph 生态讲得极其细致：ChatModel/BaseChatModel、消息类型（SystemMessage/HumanMessage/AIMessage/ToolMessage）、Runnable（invoke、abatch、with_structured_output）、工具定义与参数注入（tool、StructuredTool、InjectedToolArg）、StateGraph 节点/边/条件分支、checkpointer、reduce 操作符、MCP（MultiServerMCPClient）、模型路由与回退（build_resilient_model）、异步并发（asyncio、max_concurrency）在代码中的具体用法。
- Pydantic 模型、类型注解、依赖注入、装饰器等通用概念也顺带通俗解释。
- 全程保持上下文追踪：讲解每个新模块时，先回顾它与已讲模块之间的调用关系和代码位置，再展开细节。
