# OpenCompete 官方 RACE 量化评估实现计划

## 1. 冻结边界

- 固定官方 Deep Research Bench 提交 `469cce54ea7f6a63c163d3d9fec879cf289ec484`。
- 官方仓库和数据通过外部目录获取，不复制到 `src/opencompete`。
- OpenCompete 只生成官方 `{id, prompt, article}` JSONL、运行侧车指标和中文量化摘要。
- 官方 RACE、兼容本地 RACE、OpenCompete Local Bench 使用不同名称。
- 不新增数据库、服务、前端、分布式调度或自定义综合总分。

## 2. 实施步骤

1. 为官方 Query JSONL、目标 Article JSONL 和官方结果建立最小 Pydantic 契约。
2. 增加不依赖 Agent Server 的 ODR 通用任务 Runner，逐题追加结果并支持跳过已完成 ID。
3. 每题保存状态、时长、Token、Tavily 调用和成本侧车，不把秘密或响应正文写入错误记录。
4. 生成前验证官方仓库 HEAD 与固定提交一致，验证 100 个唯一任务。
5. 运行中英文 3–5 题冒烟，人工核对报告与官方输入格式。
6. 通过官方 evaluator 生成四维与 Overall；不同 Judge 模型使用不同结果标签。
7. 输出成功样本数、完成率、四维均分、Overall、成本与失败分类。
8. 同配置运行固定上游与 OpenCompete，输出逐指标绝对差值。
9. 冒烟通过后才运行全部 100 题。
