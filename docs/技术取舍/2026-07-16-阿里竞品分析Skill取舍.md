# 阿里竞品分析 Skill 取舍记录

> 决策日期：2026-07-16  
> 审查对象：`C:\Users\ZJW\.qoderworkcn\plugins\product-management\skills\竞品分析\SKILL.md`  
> 结论：不整包接入；只把少量方法论作为未来可选 `product_strategy` Analysis Pack 的需求参考。

## 1. 已确认需求

OpenCompete 第一版需要的是通用、可恢复、证据可追溯的竞品研究与报告系统。正式链路必须满足冻结范围、Source/Evidence/Claim/Comparison、Unknown/partial、硬预算、本地持久化和可复现评测；不得依赖 Agent Server、Notion、Figma 或其他连接器。

阿里 Skill 的主要能力是按产品设计、融资 BP、战略规划和年度汇报选择模板，输出功能矩阵、SWOT、Porter 五力、定价、定位、战略推演和差异化建议。它还包含来源可信度、时效、事实与推断分离等质量要求。

## 2. 删除后的后果

| 候选能力 | 不纳入第一版的后果 | 是否违反已确认需求 |
|---|---|---|
| 功能/定价矩阵 | 当前仍可用通用层级和维度生成比较，只缺少固定展示模板 | 否 |
| SWOT、五力、定位矩阵 | 第一版不会自动产出产品战略咨询框架 | 否；这属于可选分析方法，不是报告闭环必需条件 |
| 战略推演和差异化三层策略 | 当前报告更偏证据研究，不直接给出路线图与工作量建议 | 否；未经证据约束的推演反而可能违反 FACT 边界 |
| 信息可信度与时效标注 | 如果完全忽略会削弱来源评价 | 是；但 OpenCompete 已通过 Source、时间、证据和 FACT 契约独立实现 |
| Notion/Figma 增强 | 不能自动写团队知识库或引用设计稿 | 否；个人本地第一版明确不需要连接器 |

## 3. 成熟方案评估

| 维度 | 评估 |
|---|---|
| 需求匹配 | 方法论模板有参考价值，但没有 SQLite 恢复、范围冻结、结构化证据链、预算或 RACE/FACT 契约 |
| 维护与版本 | 本地插件文件没有独立版本、变更日志或可验证的公开维护地址，不能作为稳定运行依赖 |
| 许可证 | 当前文件未提供可独立审计的复用许可证，因此不复制其大段文本或模板到产品代码 |
| 安全 | 可选 Notion/Figma 连接器会扩大权限与秘密边界；第一版没有对应需求 |
| 测试能力 | Skill 是提示式流程，没有可直接复用的确定性 DTO、门禁或自动测试 |
| 供应商锁定 | 整包依赖 Qoder 插件目录会使 OpenCompete 无法独立安装和运行 |
| 退出成本 | 若只记录方法论映射，未来可随时替换；若复制整套模板，后续与证据模型同步成本高 |

## 4. 选择与最小自研

不把该 Skill 作为运行时、Prompt 包或代码依赖，也不读取它来决定正式任务范围。OpenCompete 保持自身的通用 Scope、证据链和确定性报告渲染。

未来只有在用户明确需要“产品战略分析包”时，才考虑增加可选 `product_strategy` Analysis Pack。最小边界是：

1. 把功能矩阵、SWOT、五力、定位和战略推演表示为显式维度或派生视图。
2. 每条事实仍必须引用已有 Evidence；推断必须单独标记信心度和依据，不得冒充事实。
3. 不引入 Notion/Figma 连接器；若未来出现真实需求，再单独设计权限、秘密和退出策略。
4. 不把模板评分直接当 RACE/FACT；报告质量评测仍使用固定 Case、Criteria、Reference Report 和 Claim-Evidence 关系。

## 5. 重新评估触发条件

- 用户明确要求产品设计、融资 BP、战略规划或年度汇报的固定交付模板。
- 现有八个基准案例完成具名人工审核后，证明某一方法论能稳定提高报告质量。
- 出现需要 Notion/Figma 的真实工作流，并且权限、秘密与持久化需求已经确认。
- 该 Skill 获得可审计的公开版本、许可证和自动测试契约。

在触发条件出现前，整包接入只会增加提示、连接器和供应商耦合，不对应当前必须需求，因此维持“不接入、只参考”的决定。
