项目架构与工作流

基于 LangGraph 的本地竞品研究系统：先确认研究边界，再由分层 Agent 检索与综合，最终保存可阅读报告和可审计证据。

当前源码：0e23fb92026-10-11本地 · 单用户Python / LangGraph / Vue / FastAPI

读图顺序：交互入口 → ApplicationRunner → 父图内的范围、研究与产物处理 → 本地存储。右侧是共享的预算、模型运行时及外部服务。

任务工作流｜从一个问题到一份报告

按编号阅读；研究阶段存在两层循环

关键边界：人工确认后冻结范围；Researcher 把压缩笔记与证据一起回传；生成完整报告后，再提取和校验证据链。评测在发布后按需启动。

Runner 管生命周期，Graph 管步骤

Runner 组装配置、锁、Saver 和预算，负责执行、恢复与发布。父图管理确认与产物处理；研究子图保留上游 Supervisor / Researcher 职责。

执行状态与业务产物分开保存

SQLite Checkpoint 支持确认点和跨进程恢复；Run Repository 提供历史报告与证据。恢复时按 run_id、revision 与哈希对账，SQLite 与文件之间没有跨存储事务。

报告可读，结论有证据索引

report.md 保存完整叙事；bundle.json 保存来源、摘录、结论与比较。证据不足显式记录 Unknown。结构引用完整，不等于事实语义已经被证明。

沿着一次真实任务，理解八个阶段
  1. 创建任务：用户在 Vue 工作台提交研究委托。FastAPI 调用 Runner 分配 run_id、保存配置快照和初始 Manifest，返回 HTTP 202；范围规划在本地后台协程执行。CLI 使用同一个 Runner 的 ResearchRequest 入口。
  2. 形成范围草案：Web 委托经 ScopePlanner 规划研究对象、层级、分析维度与排除项。可选发现通过 Tavily 佐证候选；有候选时先用 durable interrupt 等待用户选择。
  3. 人工确认并冻结：最终 Scope 再经过一次 interrupt。用户接受后冻结范围；拒绝则取消。网页、Provider 和后续提取器都不能自行把范围外对象纳入正式结论。
  4. 准备研究输入：父图生成面向模型的研究说明和留在状态中的 ResearchContract。嵌入的上游子图关闭重复澄清，再通过 write_research_brief 为 Supervisor 建立研究任务书与上下文。
  5. 分派、检索与回传：Supervisor 发出 ConductResearch，多个 Researcher 并行研究不同主题。每个 Researcher 在模型与搜索工具之间循环，随后压缩笔记，并把工具证据 artifact 一起回传。Supervisor 综合结果后可以继续分派，直到研究完成或达到受控停止条件。
  6. 综合与结构化：最终报告节点根据任务书和研究笔记生成完整叙事。materialize 从工具记录捕获 Source / Evidence，再由 Artifact Extractor 结构化提取 Claim / Comparison，清洗越界引用并补齐 Unknown。提取器与最终报告使用独立输出 token 配置。
  7. 校验和发布：检查 ID、引用、范围、维度与比较上下文。Runner 将 Bundle、报告与 Manifest 发布到同一 run_id 的目录；文件逐个原子替换，Manifest 最后写。预算耗尽或研究不完整时按 partial 保留可用成果；无法发布的错误标记 failed。诚实的 Unknown 本身不必然导致 partial。
  8. 读取与评测：Web 可以阅读报告并从结论查看摘录和来源。评测是独立命令：读取已有报告与 Bundle，可调用 Judge，但不重新搜索，也不修改原始产物。RACE、FACT、硬门禁、完成率与成本分别报告。
结论如何追溯：从报告查回原文来源

Source → Evidence → Claim → Comparison → ReportArtifact

Source 保存公开来源 URL、标题等元数据；Evidence 保存摘录或结构化值，以及来源引用、位置和质量标记；Claim 关联对象、维度与 evidence_ids；Comparison 引用同一比较上下文中的结论；ReportArtifact 同时保留 Markdown 正文与引用索引。

例如，若系统给出“某产品支持私有部署”，应能沿 Claim 找到 Evidence 中的具体摘录，再打开 Source URL 核对。这里仅演示数据关系，不代表某次研究的实际结论。

新 Run 的证据来自工具返回的 artifact，不能仅凭模型在自由文本中编造的来源标记建立可信来源。提取器只能引用已捕获证据；无效引用被清洗，无法支持时记录 Unknown 与原因。

门禁检查的是结构与范围一致性。正文没有被强制改写成逐条 Claim 模板，也没有保证每句话都自动完成语义验证；评测与人工回查仍有独立作用。

可靠性如何贯穿全流程：预算、重试与恢复

预算：BudgetGuard 在外部调用前预留，完成后结算；持久化账本保留预算与调用记录。预算不足时停止新增调用，利用已有材料生成部分结果。

模型重试：在配置完成的单个 LangChain Runnable 边界重试。默认主模型最多 3 次、备用最多 2 次；只有限流、超时、连接异常与 HTTP 5xx 等临时错误触发降级。正式默认关闭 SDK 内部重试，避免一次可见尝试对应多次隐藏请求。call_id 追踪逻辑调用，attempt_id 追踪实际尝试；成功的并行兄弟调用不因另一个调用的自动重试而整图重跑。

中断恢复：父图注入官方 AsyncSqliteSaver，框架负责嵌入子图的命名空间。重新启动进程后，以同一 run_id 恢复；确认点需要用户输入。恢复前核对 Checkpoint 与业务文件的 revision 和一致性，再决定继续图、修复发布或返回已发布结果；不承诺所有外部副作用恰好执行一次。

用户反馈：事件记录当前阶段、主备模型、尝试次数与等待时间，CLI 展示进度，Web 经 SSE 回放历史并续播实时事件。密钥保留在环境变量或进程内 Provider 对象，不能进入 State、Checkpoint 或业务产物。

运行边界：当前以本地单用户运行，同一进程用 asyncio.Lock 保护同一个 Run；不支持两个进程同时恢复同一任务。
