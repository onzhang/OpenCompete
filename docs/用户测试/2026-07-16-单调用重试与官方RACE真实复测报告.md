# OpenCompete 单调用重试与官方 RACE 真实复测报告

## 1. 测试目标

本次复测验证以下已确认需求：

1. 删除 Application Runner 的整图重试，模型故障只重试当前逻辑模型调用。
2. 单个自动执行窗口最多主模型三次、备用模型两次，只对限流、超时、连接错误和 HTTP 5xx 重试或降级。
3. 并行 Researcher 中一个调用失败时，不重放已经成功的兄弟调用。
4. 用户端继续展示阶段、主备模型、总尝试进度、等待时间和脱敏错误。
5. 使用官方 Deep Research Bench 固定 100 题仓库，真实生成中文和英文报告，并通过官方 evaluator 产生量化结果。
6. Judge 模型不是官方 GPT-5.5 时，结果必须标记为 `race_compatible_local`。

正式系统仍不依赖 Agent Server、LangSmith 或 MCP。

## 2. 测试环境

- 操作系统：Windows
- 项目目录：`D:\web-code\OpenCompete\opencompete`
- 官方 DRB 固定提交：`469cce54ea7f6a63c163d3d9fec879cf289ec484`
- 生成模型：`openai:gpt-5.6-luna`
- 兼容 RACE Judge：`gpt-5.6-luna`
- 搜索：Tavily
- 备用模型：通过本地 `.env` 的 Anthropic 兼容配置提供
- API Key 与 Base URL：只检查是否存在，不写入命令、日志、报告或产物

## 3. 主要实现变更

- 新增 `src/open_deep_research/model_routing.py`，只薄封装 LangChain 官方 `with_retry` 和 `with_fallbacks`。
- 在结构化输出、工具绑定、网页摘要、压缩、最终报告和 Artifact Extractor 的单次 Runnable 边界接入主备路由。
- 删除 `src/opencompete/model_runtime.py` 及整图重试测试。
- Application Runner 的每次 invoke/resume 只执行一次 Graph。
- 预算回调继续用稳定 `call_id` 记录每次真实请求，并增加供应商、模型、主备身份、窗口尝试数和重试计划字段。
- 单个 Researcher 主备尝试耗尽后转为隔离失败，保留同批成功研究结果。
- DRB evaluator 子进程固定 UTF-8，并只对当前 OpenAI 兼容 Provider 主机绕过系统代理。
- DRB `score` 增加 `--id` 子集能力，临时 Query 文件仍来源于已验证的官方 100 题，不修改 Criteria、Reference、公式或 evaluator。

## 7. 真实失败与修复记录

### 7.1 Windows 默认 GBK 读取官方 UTF-8 失败

首次 evaluator 启动在读取 `query.jsonl` 时出现 `UnicodeDecodeError`，尚未调用 Judge。

修复：只在官方 evaluator 子进程设置 `PYTHONUTF8=1`，不修改官方固定提交。

### 7.2 系统代理导致 `requests` 链路断开

主系统的 LangChain/httpx 已能访问 Provider，但官方 evaluator 使用 `requests` 并继承系统代理，出现 `ProxyError` 和连接重置。

修复：从 `OPENAI_BASE_URL` 解析 Provider 主机，只把该主机追加到 evaluator 子进程的 `NO_PROXY`；单独真实连通测试返回 `OK`。

### 7.3 官方 `--limit` 不能正确处理混合语言子集

官方 `--limit 1` 会在中文阶段只清洗第一篇报告，英文阶段找不到任务 51。

修复：`score --id 1 --id 51` 从已验证的官方 Query 生成临时子集文件；Criteria、Reference、评分 Prompt、公式和 evaluator 代码保持官方版本。

### 7.4 终端混合编码

子进程固定 UTF-8 后，父进程仍使用 Windows GBK，直接共享输出流会造成进度条和中文表格乱码。

修复：父进程按 UTF-8 捕获官方子进程输出，再由当前终端统一编码输出。

## 8. 最终结论

本次真实复测证明：

1. OpenCompete 已不再依赖整图重试；模型故障边界下移到单次 Runnable。
2. 主三备二、永久错误立即停止、并行成功调用不重放均有离线测试覆盖。
3. 官方 DRB 中文和英文报告均完成真实搜索、分析、报告生成和逐题持久化。
4. 官方 evaluator 已通过当前兼容 Judge 完成 2/2 量化评分，结果严格标记为 `race_compatible_local`。
5. 报告正文无系统内部 ID，标题结构稳定，长度能够体现长时间研究价值。
6. 当前结果是两题真实冒烟，不代表 100 题总体成绩；运行全部 100 题前应先确认长期成本和执行时间安排。
7. 对本次 DRB 目录内 10 个文件执行环境秘密值、`Authorization:` 和 `Bearer` 扫描，结果通过。
