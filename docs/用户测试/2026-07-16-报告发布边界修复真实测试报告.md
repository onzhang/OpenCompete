# OpenCompete 报告发布边界修复真实测试报告

## 1. 测试目标

验证成功的上游完整报告不会再被 Artifact Extractor 或确定性 Renderer 替换，同时保持候选确认、冻结范围、结构化证据链、SQLite 持久化、CLI 查看和秘密扫描可用。

## 2. 测试内容

1. 候选发现后只批准用户研究目标中明确指定且可识别的 `Cursor`，拒绝把任意网页标题当成竞品。
2. 完成候选确认和最终 Scope 确认后启动正式研究。
3. 验证最终报告不少于 5,000 字符且至少包含四个二级章节。
4. 验证报告正文不包含 Bundle 中任何 Source、Evidence、Claim 或 Comparison 内部 ID。
5. 验证 Source、Evidence、Claim、Comparison 均非空，且结构化追溯违规为零。
6. 使用新 Runner 重新加载产物，并由独立 CLI `show` 展示同一份报告。
7. 扫描 SQLite 和全部本地产物，确认 API Key 与 Authorization 模式未落盘。

## 5. 结论

修复后的 `report.md` 是包含摘要、产品分析、逐项比较、事实与推断边界、Unknown、最终结论和 Sources 的完整用户报告。结构化 Bundle 继续独立承担 FACT、硬门禁和追溯；确定性 Renderer 只保留为报告模型失败时的无内部 ID 保底路径。

真实报告仍出现个别二级与三级标题深度不一致。系统没有增加后处理或第二次模型调用，而是在现有最终报告 Prompt 中明确唯一 H1、H2 顶级章节和 H3 子章节规则；该规则由离线回归测试锁定。
