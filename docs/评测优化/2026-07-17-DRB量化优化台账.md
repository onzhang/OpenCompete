# DRB 量化优化台账

## 目的

本台账持续记录 OpenCompete 共享研究 Graph 的优化过程，回答四个问题：

1. 使用了什么优化策略；
2. 主要改善 RACE 的哪个维度；
3. 优化前后量化指标如何变化；
4. 该策略最终保留、调整还是否决。

官方 DRB 只评价共享研究与报告生成内核，不代表竞品发现、Scope 冻结、Artifact Extractor、硬门禁或持久化质量。进入正式产品前，还必须通过固定 Scope 的真实 OpenCompete 内核测试。

## 固定评测契约

- 官方仓库提交：`469cce54ea7f6a63c163d3d9fec879cf289ec484`
- 生成模型：`openai:gpt-5.6-sol`
- 官方 Judge：`gpt-5.5`
- 结果类型：`official_race`
- 基线任务：`1, 8, 16, 21, 25, 51, 58, 66, 71, 75`
- 筛选任务：基线中最弱的 `51, 71, 75`
- 主分数：RACE Overall
- 独立观察项：四维分数、完成率、运行时间、模型用量、Tavily 调用和本地估算成本

所有优化必须使用相同任务、官方 Criteria、Reference Report、Judge 和 evaluator 代码进行配对比较。FACT、硬门禁与成本不合成为自定义总分。

## 实验 E01：同时扩大研究上下文与最终报告容量

### 假设

302 次 Tavily 搜索经过单个 Researcher 仅 800 token 的压缩，并在最终写作前限制为 24,000 字符，可能造成信息损失。提高容量应改善 Comprehensiveness 与 Instruction Following。

### 唯一配置变化

| 配置 | 基线 | E01 |
|---|---:|---:|
| `compression_model_max_tokens` | 800 | 2000 |
| `final_report_input_max_chars` | 24000 | 60000 |
| `final_report_model_max_tokens` | 6000 | 10000 |

研究 Graph、Prompt、模型、Tavily、并发、搜索轮次和重试策略保持不变。

### 执行异常记录

1. 第一次启动因实验配置目录旁没有 `.env`，三题在模型初始化前零调用失败；不计入质量结果。
2. 第二次启动遇到临时模型 Provider 故障，三题均未进入 Tavily 搜索；约产生 0.50 美元模型预留/调用成本，不计入质量结果。
3. 主模型连通性恢复后第三次生成成功。
4. 首次评分进程被外部终止，未生成任何清洗或评分结果；改用隐藏后台进程后断点评分成功。

### 三题有效结果

| 指标 | 基线 | E01 | 变化 |
|---|---:|---:|---:|
| Comprehensiveness | 0.5336 | 0.5438 | +0.0102 |
| Insight | 0.5386 | 0.5362 | -0.0024 |
| Instruction Following | 0.5300 | 0.5363 | +0.0063 |
| Readability | 0.5370 | 0.5218 | -0.0152 |
| Overall | 0.5349 | 0.5365 | +0.0016 |

### 任务级变化

| 任务 | Overall | Comprehensiveness | Insight | Instruction Following | Readability |
|---|---:|---:|---:|---:|---:|
| 51 | -0.0058 | +0.0114 | -0.0171 | +0.0038 | -0.0307 |
| 71 | +0.0089 | +0.0126 | +0.0103 | +0.0112 | -0.0081 |
| 75 | +0.0018 | +0.0068 | -0.0003 | +0.0039 | -0.0067 |

### 成本与长度

| 指标 | 基线三题均值 | E01 三题均值 | 变化 |
|---|---:|---:|---:|
| 本地估算成本 | 1.5676 美元 | 1.7500 美元 | +11.6% |
| 运行时间 | 779.21 秒 | 902.40 秒 | +15.8% |
| Tavily 调用 | 29.67 | 29.00 | -2.2% |

报告字符数变化：任务 51 `+36.2%`，任务 71 `+54.4%`，任务 75 `+33.7%`。

### 根因分析与取舍

- 容量提升确实改善了覆盖度和指令遵循，假设得到部分验证。
- `final_report_model_max_tokens = 10000` 同时造成报告膨胀和结构碎片化。
- 任务 51 标题从 26 个增加到 51 个，表格行从 60 增加到 192；报告在半张表格处截断，最终没有任何 URL。
- 任务 71 标题从 28 个增加到 69 个。
- Readability 明显退化，Overall 提升不足以抵消成本和风险。

结论：**E01 整体否决，不进入正式配置；保留“扩大研究压缩和写作输入”作为待拆分验证的候选，否决“同时扩大最终报告输出”。**

## 实验 E02：扩大研究上下文，但恢复最终报告输出上限

### 状态

已完成，方案否决。

### 配置

| 配置 | 基线 | E02 |
|---|---:|---:|
| `compression_model_max_tokens` | 800 | 2000 |
| `final_report_input_max_chars` | 24000 | 60000 |
| `final_report_model_max_tokens` | 6000 | 6000 |

### 验证目标

- 保留 E01 在 Comprehensiveness 和 Instruction Following 上的收益；
- Readability 不得比三题基线下降超过 `0.005`；
- 报告必须完整结束，包含 Sources，不得停在半个段落或表格；
- 若 Overall 提升不足 `0.005`，不直接进入 10 题确认阶段。

### 执行稳定性记录

- 首轮任务 71 在研究后半段遇到临时 Provider 错误，消耗 35 次 Tavily 和约 1.64 美元，但没有形成有效报告。
- 失败记录保存于实验目录 `failed-attempts.jsonl`，不计入质量均值。
- 只重跑任务 71，任务 51、75 没有重复生成。

### 成本变化

| 指标 | 基线三题均值 | E02 三题均值 | 变化 |

### 取舍

- 只扩大研究上下文没有稳定改善 Comprehensiveness、Insight 或 Overall。
- Instruction Following 的微小提升不足以抵消其他维度退化。
- 说明主要瓶颈不是简单容量，而是缺少显式需求覆盖计划、缺口驱动研究和写作阶段的完成约束。

结论：**E02 否决，不进入 10 题确认；停止继续做同类容量微调，转入 L1 结构化覆盖优化。**

## 去重后的优化方向清单

以下项目按改动由轻到重排列。一个策略只保留一个主条目，其他受益维度作为次要影响，避免重复。

| 级别 | 优化方向 | 主要维度 | 次要维度 | 成熟来源 | 当前取舍 |
|---|---|---|---|---|---|
| L0 | 调整研究压缩与最终写作输入容量 | Comprehensiveness | Instruction Following、Insight | 当前框架配置能力 | E01、E02 已量化否决 |
| L0 | 最终报告长度、完整结束与 Sources 门禁 | Readability | Instruction Following | 官方 DRB 长文清洗与现有报告 Prompt | E01 已证明必要，待单独设计 |
| L1 | 从原始请求生成显式覆盖清单，研究完成前逐项核对 | Instruction Following | Comprehensiveness | LangChain `deepagents` Deep Research 的 TODO 与 Verify 工作流 | 推荐的首个 Prompt/状态优化候选 |
| L1 | 统一标题层级、限制过度分节、表格只用于高密度比较 | Readability | Comprehensiveness | LangChain `deepagents` 报告写作指南 | 待容量实验后执行 |
| L1 | 对数据、案例、因果解释和不确定性建立证据综合要求 | Insight | Comprehensiveness | GPT Researcher 的 learnings 与 follow-up questions | 待 Insight 明确退化或停滞时执行 |
| L2 | Supervisor 持久维护“已覆盖/未覆盖”计划并按缺口追加研究 | Comprehensiveness | Instruction Following | Skywork Planning Agent、GPT Researcher 递归 follow-up | 仅在 L1 清单不足时引入 |
| L2 | 先生成报告大纲和章节预算，再按大纲综合报告 | Readability | Comprehensiveness、Instruction Following | Alibaba WebWeaver outline-first writer | E01 暴露结构膨胀后成为候选，但需设计批准 |
| L2 | 报告生成后执行一次轻量检查，只修补遗漏或截断 | Instruction Following | Readability | evaluator-optimizer / verify 工作流 | 仅在无法通过单次生成稳定完成时引入 |
| L3 | Context Builder 与 Report Writer 分离、使用持久知识库按章节取材 | Comprehensiveness | Insight | FS-Researcher 类双代理方案 | 当前过重，否决 |
| L3 | 自动反思优化 Prompt 或多轮自我改写 | 全部 | 成本、稳定性风险 | Skywork Reflection Optimizer | 数据量和稳定性不足，当前否决 |

## 采用门禁

1. 先在固定弱项任务上筛选，不因报告更长或主观观感直接接受。
2. 筛选通过后，用固定 10 题和同一 GPT-5.5 Judge 完整确认。
3. Overall 是主分数；四维必须独立展示，目标维度提升不得依赖其他维度显著退化。
4. 任何共享 Graph 优化进入正式产品前，还必须通过固定 Scope 的真实 OpenCompete 内核测试。
5. 每轮只改变一个可解释的策略包；失败运行、Provider 故障和无效分数单独记录，不混入质量均值。
